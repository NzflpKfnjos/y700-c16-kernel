# Y700 四代 ColorOS 移植包：6.6 → 6.12 工程记录

分析日期：2026-10-16；进展更新：2026-10-17（Asia/Singapore）。状态：离线检查、公开源码核对、GitHub Actions 组件构建和独立 9008 候选组装已完成；候选包仍**没有经过真机 9008/Firehose 实刷和启动验证**。本记录采用普通固件分析结构（flavor=null）。

## 结论和当前缺口

此包的内核确为 `6.6.89-android15-8-g14220ae4ce65-ab13680582-4k`。系统层是 Android 16/API 36，厂商层是 Android 15/API 35；将系统层升级到 Android 16 并不会自动升级内核。包内标识指向 `TB322FC_CN / elden / sun`，ODM 中还保留一加 `OPD2413 / OP615E / SM8750` 标识，符合用户描述的混合移植结构；这些是镜像中的属性，尚未用真机确认。

跨 6.6 到 6.12 不享有同一 ACK 分支的 KMI 稳定保证。这里涉及第一阶段驱动、GKI 模块、厂商模块和设备树的成套迁移。仅替换 `boot.img` 中的 Image，无法提供与现有驱动兼容的保证。

已找到有实质 elden 适配内容的社区 `elden-6.12` 三仓，并将 common、Qualcomm Kleaf、工具链和依赖组装为 42 项目冻结 manifest，见 [CI 源码锁](../ci/source-lock.json)。本机为 macOS arm64，用户已授权使用 GitHub Actions 的 Linux x86_64 runner 构建；第三轮 Actions 已成功完成真实编译和组件检查。随后已在本地以原包为基线组装 9008 静态候选。完整经过见 [Actions 构建记录](kernel-upgrade/actions-build.md)。真机 9008 刷写、6.12 启动和硬件验证仍未完成；此前 `adb devices -l` 和 `fastboot devices` 均未列出设备。

## 已确认的本地结构

- `boot.img`：96 MiB，Android boot header v4；Image 为未压缩 ARM64 内核，36,461,056 字节；没有 boot ramdisk。
- `init_boot.img`：8 MiB，header v4；通用 ramdisk 中未发现 `.ko`。
- 内核配置：`CONFIG_ARM64_4K_PAGES=y`、`CONFIG_MODVERSIONS=y`、`CONFIG_MODULE_SIG_PROTECT=y`、`CONFIG_TRIM_UNUSED_KSYMS=y`；不能只改版本字符串或关闭版本检查来完成 ABI 移植。
- `vendor_boot.img`：96 MiB，header v4，DTB 区 6,505,644 字节、13 棵 SoC DTB；整个 vendor ramdisk 区解压后有 329 个 `.ko`，全部包含 `__versions` 符号版本记录，vermagic 均以 6.6.89 开头。DTB 包含多个 SoC 变体，不能将全部变体当作当前设备的运行配置。
- `super.img`：raw 22 GiB，liblp v10.0；元数据几何、header、tables 校验通过。包含 15 个非空逻辑分区，检查到的文件系统均为 EROFS。没有对整个 22 GiB 镜像计算或验证 SHA256。
- `system_dlkm_a`：7,372,800 字节，96 个 `.ko`；抽样 `6lowpan.ko` 与 Image 的完整构建版本一致。
- `vendor_dlkm_a`：56,971,264 字节，302 个 `.ko`；抽样显示、GPU、热控、触摸驱动属于 6.6.89，包含 `__versions`。三个模块位置存在重复文件，数量不能相加解释为独立驱动数。
- `boot/init_boot/vendor_boot/dtbo/vbmeta/vbmeta_system` 六个源镜像的 SHA256 全部与包内 `SHA256SUMS.txt` 相符。两个 vbmeta header 的 flags=0；这不能证明设备当前的 bootloader 锁定状态，也不等于已验证签名。

### 导入和依赖检查（E-imports）

ARM64 Image 没有普通用户态 ELF 的动态导入表。本轮用 `.ko` 的 ELF `.modinfo`、未定义符号和 `__versions` 作为内核依赖的等价证据，未进行函数反汇编。

例如 `vendor_boot` 中 `msm_drm.ko` 有 771 个未定义符号、772 个版本记录，依赖 `nvt_36xxx`、`panel_event_notifier`、`hqsysfs`、`qcom-scm`、USB/显示辅助模块等。`ufs-qcom.ko` 依赖 UFS PHY、加密、时钟和调度模块。`nvt_36xxx.ko` 依赖面板通知接口和联想扩展接口。还存在 `oplus_network_*` 等一加模块。因此即使内核单独编译成功，仍需保持跨驱动及用户态 HAL 使用的接口。

当前模块存在多个本地版本后缀，这是观察结果，不能单凭后缀差异断定现有 6.6 包无法启动。跨到 6.12 的问题涉及真实符号、结构体和行为兼容，而非这些字符串本身。

## 9008 候选包（2026-10-17）

候选目录为 `.work/9008-candidate-c16-6.12`，以 `c16-300-9008-V17.6` 为唯一基线。原始包没有修改；候选保留六个 rawprogram XML 和其他分区，仅替换 `boot.img`、`vendor_boot.img`、`dtbo.img`、`super.img`、`vbmeta.img`。候选目录中的 `README-9008.md` 和 [9008 候选包说明](kernel-upgrade/9008-candidate.md) 记录了镜像来源、校验命令、回滚方式和功能缺口。

静态验收已通过：80 项 SHA-256 清单、101 个 XML program 条目、分区尺寸和文件引用、boot/vendor_boot/dtbo/init_boot/recovery/vbmeta_system AVB、顶层 vbmeta 的三个 chain descriptor 和三个变更分区 hash descriptor，以及 super 三个 metadata slot。该结果只证明候选包结构和签名可解析，不证明设备上的 Firehose 接受、启动或硬件功能。

### 既有 vendor ramdisk 表异常

`vendor_boot` header 声明 ramdisk 区 9,045,827 字节，但唯一 fragment table entry 只覆盖 8,600,304 字节。按 entry 截取的数据用 lz4 解压返回 `Error 63`；按 header 的整个区域解压成功，得到 32,413,960 字节，329 模块统计来自后者。

这是原包中可复现的元数据不一致；本轮没有修补源文件，也没有据此断言它在真机上不能启动。未来重打包必须重新生成正确的 fragment 表、大小和偏移，并核对设备 bootloader 实际使用的路径。

### VINTF 的实际边界

厂商 `manifest_elden_prc_wifi.xml` 的 `target-level=202404`。系统携带的 202404 matrix 包含 6.6 内核配置要求，202504 matrix 包含 6.12 要求。多个 matrix 同时存在是静态事实，不能由此判断设备当前实际选中哪套要求，也不能推出 Android 16 系统必须换成 6.12。升级后仍需用真实内核配置、manifest 和目标 FCM 组合做 `checkvintf` 验证。

## 复现离线检查

在项目根目录执行。第一条依赖 Python 3 和 lz4；第二条的 LP 元数据检查只需 Python 3；最后一条采样提取另外依赖 `dump.erofs`。

```sh
python3 tools/inspect_boot.py --images c16-300-9008-V17.6/images --out .work/preflight
python3 tools/inspect_super.py c16-300-9008-V17.6/images/super.img
python3 tools/inspect_super.py c16-300-9008-V17.6/images/super.img --collect --erofs-tool .work/super-inspection/erofs-utils/1.9.4/bin/dump.erofs
```

`dump.erofs` 是隔离放置的 Homebrew erofs-utils 1.9.4，不是仓库内必带依赖；出处和哈希见 [工具来源](kernel-upgrade/tool-provenance.json)。其他 Linux 环境可显式传入本地 `dump.erofs` 路径。super 采样读取器只接受所需数据都落在首个线性 extent 内的路径，遇到跨 extent 会拒绝；不是通用 EROFS 解包器。LP 校验限于当前 slot 0，未验证全部 slot 和备份副本。源镜像均只读打开，输出在 `.work/`。
